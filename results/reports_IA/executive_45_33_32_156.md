# Reporte Ejecutivo de Mitigación

## Resumen de Hallazgos

El escaneo de red realizado en la dirección IP **45.33.32.156** ha identificado un total de **2 puertos abiertos**. A continuación se detallan los servicios detectados y su evaluación de riesgo:

### Servicios Identificados

1. **Puerto 22 - SSH**
   - **Servicio**: OpenSSH
   - **Banner**: SSH-2.0-OpenSSH_6.6.1p1 Ubuntu-2ubuntu2.13
   - **Sistema Operativo Adivinado**: Linux/Unix
   - **Riesgo**: **BAJO**
     - SSH es un protocolo seguro para la administración remota. Se recomienda mantener actualizada la versión de OpenSSH para mitigar vulnerabilidades conocidas.

2. **Puerto 80 - HTTP**
   - **Servicio**: HTTP
   - **Banner**: HTTP/1.1 200 OK
   - **Sistema Operativo Adivinado**: Linux/Unix
   - **Riesgo**: **MEDIO**
     - El servicio HTTP está expuesto y puede ser vulnerable a ataques como inyección de código, XSS, entre otros. Se recomienda implementar medidas de seguridad adicionales.

## Mitigación

### Para el Servicio SSH (Puerto 22)
- **Acciones Recomendadas**:
  - Asegúrese de que la versión de OpenSSH esté actualizada a la última versión estable para evitar vulnerabilidades.
  - Implementar autenticación basada en claves en lugar de contraseñas para mejorar la seguridad.
  - Deshabilitar el acceso SSH para el usuario root y utilizar cuentas de usuario con privilegios limitados.
  - Configurar el firewall para permitir el acceso SSH solo desde direcciones IP específicas.

### Para el Servicio HTTP (Puerto 80)
- **Acciones Recomendadas**:
  - Considerar la implementación de HTTPS utilizando un certificado SSL/TLS para cifrar la comunicación y proteger la información sensible.
  - Realizar pruebas de penetración periódicas para identificar y remediar vulnerabilidades en la aplicación web.
  - Implementar un firewall de aplicaciones web (WAF) para proteger contra ataques comunes como inyección SQL y XSS.
  - Mantener actualizados todos los componentes del servidor web y las aplicaciones alojadas.

## Conclusión

Los hallazgos del escaneo de red indican que, aunque el servicio SSH está configurado de manera segura, el servicio HTTP expone la infraestructura a riesgos potenciales. Se recomienda implementar las acciones de mitigación sugeridas para fortalecer la seguridad de la red y proteger los activos críticos.
