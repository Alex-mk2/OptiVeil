# Reporte Ejecutivo de Mitigación

## Resumen de Hallazgos

Se ha realizado un escaneo de red sigiloso sobre el objetivo `186.64.114.50`, identificando un total de 3 puertos abiertos. A continuación se detallan los servicios detectados y su evaluación de riesgo:

| Puerto | Servicio | Riesgo | Observaciones |
|--------|----------|--------|---------------|
| 21     | FTP      | CRÍTICO| Servicio en texto plano, susceptible a intercepciones. Se recomienda el uso de SFTP. |
| 25     | SMTP     | BAJO   | Servicio estándar, pero sin cifrado. Considerar implementación de STARTTLS. |
| 80     | HTTP     | BAJO   | Servicio HTTP sin cifrado. Se recomienda la migración a HTTPS. |

## Evaluación de Riesgo

1. **FTP (Puerto 21)**:
   - **Riesgo**: CRÍTICO
   - **Descripción**: El servicio FTP está transmitiendo datos en texto plano, lo que lo hace vulnerable a ataques de intercepción y suplantación. La falta de cifrado permite que credenciales y datos sensibles sean fácilmente capturados por un atacante.
   
2. **SMTP (Puerto 25)**:
   - **Riesgo**: BAJO
   - **Descripción**: Aunque el servicio SMTP es comúnmente utilizado, no se ha detectado cifrado. Esto puede permitir la interceptación de correos electrónicos si no se implementan medidas adicionales.

3. **HTTP (Puerto 80)**:
   - **Riesgo**: BAJO
   - **Descripción**: El tráfico HTTP no está cifrado, lo que puede llevar a la exposición de datos sensibles. Se recomienda la implementación de HTTPS para proteger la comunicación.

## Mitigación

### Pasos Accionables para el Administrador del Sistema

1. **Migrar de FTP a SFTP**:
   - Deshabilitar el servicio FTP en el servidor.
   - Implementar SFTP para la transferencia segura de archivos.
   - Asegurarse de que todos los usuarios sean informados sobre el cambio y se les proporcione la capacitación necesaria.

2. **Implementar STARTTLS en SMTP**:
   - Configurar el servidor SMTP para que utilice STARTTLS, permitiendo el cifrado de correos electrónicos en tránsito.
   - Verificar que todos los clientes de correo electrónico estén configurados para utilizar el cifrado.

3. **Migrar de HTTP a HTTPS**:
   - Obtener un certificado SSL/TLS para el dominio asociado al servicio HTTP.
   - Configurar el servidor web para redirigir automáticamente el tráfico HTTP a HTTPS.
   - Realizar pruebas para asegurar que todas las páginas se carguen correctamente a través de HTTPS.

### Recomendaciones Adicionales

- Realizar auditorías de seguridad periódicas para identificar y mitigar nuevas vulnerabilidades.
- Mantener todos los servicios y sistemas actualizados con los últimos parches de seguridad.
- Capacitar al personal sobre las mejores prácticas de seguridad y la importancia del cifrado en las comunicaciones.

## Conclusión

La identificación de servicios en texto plano y la falta de cifrado en la comunicación representan riesgos significativos para la seguridad de la red. Se recomienda implementar las mitigaciones sugeridas a la mayor brevedad posible para proteger la integridad y confidencialidad de los datos.
