# Reporte Ejecutivo de Mitigación

## Resumen de Hallazgos

Se ha realizado un escaneo de red sigiloso en la dirección IP **186.64.114.50**, identificando un total de **3 puertos abiertos**. A continuación se detallan los servicios detectados, junto con su evaluación de riesgo y recomendaciones de mitigación.

### Servicios Identificados

1. **FTP (Puerto 21)**
   - **Banner:** 220 You will be disconnected after 10 minutes of inactivity.
   - **Riesgo:** **CRÍTICO**
     - El servicio FTP transmite datos en texto plano, lo que lo hace susceptible a la interceptación y ataques de tipo "man-in-the-middle". Se recomienda encarecidamente deshabilitar FTP y utilizar SFTP o SCP para la transferencia segura de archivos.

2. **SMTP (Puerto 25)**
   - **Banner:** N/A (Inferido por puerto estándar)
   - **Riesgo:** **MEDIO**
     - Aunque SMTP no transmite datos en texto plano, puede ser vulnerable a ataques de spoofing y phishing. Se recomienda implementar autenticación y cifrado (STARTTLS) para proteger las comunicaciones.

3. **HTTP (Puerto 80)**
   - **Banner:** HTTP/1.1 200 OK
   - **Riesgo:** **ALTO**
     - El tráfico HTTP también se transmite en texto plano, lo que lo hace vulnerable a la interceptación. Se recomienda migrar a HTTPS utilizando TLS para cifrar el tráfico y proteger la integridad y confidencialidad de los datos.

## Recomendaciones de Mitigación

### 1. Deshabilitar FTP y Migrar a SFTP
- **Acción:** Deshabilitar el servicio FTP en el servidor.
- **Implementación:** Configurar un servidor SFTP o SCP para la transferencia de archivos.
- **Verificación:** Realizar pruebas de conectividad y funcionalidad para asegurar que los usuarios pueden acceder a los archivos de manera segura.

### 2. Implementar Seguridad en SMTP
- **Acción:** Configurar el servidor SMTP para utilizar STARTTLS.
- **Implementación:** Asegurarse de que la autenticación esté habilitada y que se utilicen contraseñas fuertes.
- **Verificación:** Realizar pruebas de envío y recepción de correos electrónicos para confirmar que la comunicación está cifrada.

### 3. Migrar de HTTP a HTTPS
- **Acción:** Obtener un certificado SSL/TLS para el dominio.
- **Implementación:** Configurar el servidor web para redirigir todo el tráfico HTTP a HTTPS.
- **Verificación:** Realizar pruebas de acceso al sitio web para asegurar que todas las conexiones se realicen de manera segura.

## Conclusión

La identificación de servicios vulnerables en texto plano representa un riesgo significativo para la seguridad de la red. Se recomienda que el administrador del sistema implemente las acciones de mitigación sugeridas a la mayor brevedad posible para reducir la superficie de ataque y proteger la integridad de los datos en la red.
