# Reporte Ejecutivo de Mitigación

## Resumen de Hallazgos
Se ha realizado un escaneo de red sigiloso en la dirección IP `186.64.114.50`, donde se han identificado tres puertos abiertos. A continuación, se detallan los servicios asociados a cada puerto, junto con su evaluación de riesgo y recomendaciones de mitigación.

### Detalles de Servicios Identificados

1. **Puerto 21 - FTP**
   - **Servicio:** FTP
   - **Banner:** `220 You will be disconnected after 10 minutes of inactivity.`
   - **Riesgo:** **CRÍTICO**
     - El servicio FTP transmite datos en texto plano, lo que lo hace vulnerable a la interceptación y ataques de tipo "man-in-the-middle". 
     - Se recomienda encarecidamente la migración a un protocolo seguro como SFTP o SCP.

2. **Puerto 25 - SMTP**
   - **Servicio:** SMTP
   - **Banner:** `N/A (Inferred by standard port)`
   - **Riesgo:** **MEDIO**
     - Aunque el servicio SMTP puede ser seguro, su configuración y uso pueden ser vulnerables a ataques de spoofing y phishing si no se implementan medidas de autenticación adecuadas.
     - Se recomienda habilitar la autenticación SMTP y el uso de TLS para cifrar las comunicaciones.

3. **Puerto 80 - HTTP**
   - **Servicio:** HTTP
   - **Banner:** `HTTP/1.1 200 OK`
   - **Riesgo:** **ALTO**
     - El tráfico HTTP también se transmite en texto plano, lo que puede ser susceptible a ataques de interceptación.
     - Se recomienda implementar HTTPS para cifrar las comunicaciones y proteger la integridad y confidencialidad de los datos.

## Mitigación

### Pasos Accionables para el Administrador del Sistema

1. **Migración de FTP a SFTP:**
   - Deshabilitar el servicio FTP en el servidor.
   - Configurar un servidor SFTP y asegurarse de que todos los usuarios tengan acceso a través de claves SSH.
   - Realizar pruebas de conectividad y funcionalidad para asegurar que todos los procesos que dependían de FTP ahora funcionen correctamente con SFTP.

2. **Fortalecimiento de SMTP:**
   - Habilitar la autenticación en el servidor SMTP para asegurar que solo los usuarios autorizados puedan enviar correos electrónicos.
   - Configurar el servidor para que utilice TLS, asegurando que las conexiones sean cifradas.
   - Monitorear los registros de correo para detectar actividades sospechosas.

3. **Implementación de HTTPS:**
   - Obtener un certificado SSL/TLS válido para el dominio.
   - Configurar el servidor web para redirigir automáticamente las solicitudes HTTP a HTTPS.
   - Realizar pruebas de seguridad en la implementación de HTTPS para asegurar que no existan vulnerabilidades como el uso de cifrados débiles.

## Conclusión
La identificación de servicios en texto plano y la falta de medidas de seguridad adecuadas representan un riesgo significativo para la infraestructura de red. Se recomienda que se implementen las mitigaciones sugeridas a la mayor brevedad posible para proteger la integridad y confidencialidad de los datos en tránsito.
